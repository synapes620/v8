--- Root cause ---
wasm-serialization.cc: NativeModuleDeserializer::ReadCode()

  Lines 1001-1018 read all code metadata fields from the blob:
    effect_handlers_size = reader->Read<uint32_t>()  // line 1018

  These reads have ONLY DCHECK guards (stripped in release):
    DCHECK_GE(remaining_code_size_, code_size)        // line 1023

  With blob_1fn (1-function blob) + wire_200fn (200-function wire bytes):
    - Function 0: reader stays within valid blob
    - Function 1: ALL metadata reads (lines 1001-1020) read from heap PAST blob end
      → effect_handlers_size = 0x1ff8 (8184) from adjacent heap bytes
    - Line 1046: reader->ReadVector(8184) returns a Vector pointing past blob end
    - Line 1047: TranslateEffectHandlersToCanonical(garbage_vector) is called
    - Line 347 (TranslateEffectHandlersTable): LEBHelper::read_u32v advances src
      pointer into unmapped memory → SIGSEGV

--- Attack primitive ---
The blob is an ArrayBuffer from an untrusted source (IPC, network cache).
In Chrome's production path (AsyncStreamingProcessor::Deserialize in
streaming-decoder.cc:428-436) there is NO hash guard:
  processor->Deserialize(module_bytes, wire_bytes)
An attacker with access to the compilation cache (compromised renderer) can
inject a mismatched blob directly to the browser process without the d8 hash guard.
The crash point is in TranslateEffectHandlersToCanonical which calls
translate_sig_id() — a lambda that calls native_module_->module() — using a
garbage sig_id read from OOB heap bytes, which may point into arbitrary memory.
